# 稿件按 BV 号去重、来源按标签去重

「增量追加」允许用户反复贴链接，必然产生同一个稿件出现多次、同一条链接被贴两次的情况。去重键选了两档：

- 稿件：`bvid.upper()` —— BV 号是 B 站全局唯一的稿件标识，大小写不敏感（用户会手输）。
- 来源：`source_label()` 的返回值 —— 单稿件是 `video-<bvid>`，列表是 `<kind>-<oid>`，天然稳定且可读。

先到先得：第一次出现的那条决定 `from`（导出时的 `source` 列）与 `parts`，后到的只补 `also_in`，
且 `also_in` 不做同标签自追加。

## Considered Options

- **用 `(bvid, page)` 或 `(bvid, cid)` 当稿件键**：那是分P的粒度，会把一个稿件的分P拆成多行。
- **用原始 url 当来源键**：同一条链接换个 query 顺序或带上 `?p=3` 就会被当成新来源。
- **合并后覆盖已有数据**：会让「先解析的分P」被「后解析但抓取失败的空 parts」冲掉。

## Consequences

- 同一来源贴两次不会多出一行、也不会多出一个来源，前端据此提示「来源已在列表里」。
- 稿件合并只发生在补分P之前，所以去重也省掉了重复抓取。
